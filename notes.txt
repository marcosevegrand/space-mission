> Exemplo:
        // OperationalState represents the current operational mode of a rover.
        type OperationalState uint8

        // Operational states that a rover can be in.
        const (
       	StateIdle      OperationalState = iota + 1 // Rover is stationary and idle
       	StateMoving                                // Rover is in motion
       	StateOnMission                             // Rover is executing a mission
       	StateError                                 // Rover encountered an error
       	StateUnknown                               // Rover state is unknown
        )

        func (os OperationalState) String() string {
       	return [...]string{"idle", "moving", "onMission", "Error", "Unknown"}[os-1]
        }

Desta forma os codecs acabam por nunca ter de serializar strings o que diminui o tamanho do payload, mas tenho receio

2. Ao implementar o UDP link, o Go fornece duas formas de trabalhar com os sockets, listen e dial que permitem criar uma relação servidor-cliente. No meu caso, a minha implementação do servidor e cliente só se distingue pelo facto de um usar listen (e portanto WriteToUDP/ReadFromUDP) e o outro dial (e portanto Write/Read). Eu acho que seria mais simples usar Listen para ambos e ter o mesmo código para o servidor e cliente que no caso acho que seriam peers.
PROVAVELMENTE PREFERIVEL USAR SÓ LISTEN
